## 一、业务诉求（调研对象说清楚的）

| 项              | 说明                                                                                                                          |
| -------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 背景             | 在游戏发行生态中，公司作为发行方是需要对一款游戏的收入流水与研发（CP 方）进行分成的                                                                                 |
| 痛点             | 公司未来在与多 CP 方合作多游戏发行时，需要将每份CP分成合同落实管理，用于业务报表与财务结算依据的数据统计。同时，一般 CP 分成需要考虑游戏发行时的渠道费用、流水支付通道费用由哪方承担，分成的流水范围及分成比例等信息，需要能在配置能力里覆盖 |
| 现状（workaround） | 无                                                                                                                           |
| 期望目标           | 提供配置模块能覆盖发行业务 CP 分成的场景诉求，支撑财务日常管理维护工作；同时配置得到的分成规则能被 BI 看板、财务结算报表的模块进行引用计算                                                   |
| 期望实现日期         | 跟随 MVP 阶段                                                                                                                   |

## 二、PM 的基本判断（PM 输出）

| 项      | 说明                                                                            |
| ------ | ----------------------------------------------------------------------------- |
| 结论     | 需要做。第一阶段把「分成方案配置 + BI 看板相关指标计算」做完整闭环                                          |
| 时间     | 跟随 MVP 阶段                                                                     |
| 原因     | 分成直接决定项目的真实回收水平，是重要的业务表现参考，同时也是财务结算时的必要依据                                     |
| 依赖条件   | 明确的 CP 合同条款，用于抽象业务场景以设计配置模块能力。考虑到业务实际阶段，这块先参考 PM 的行业经验出方案，后续根据实际 CP 合同新增条款来迭代 |
| 整体方案思路 | 见下方 2.1 与 2.2                                                                 |
| 优先级    | 跟随 MVP 阶段                                                                     |

### 2.1 规则层面：支持配置三类内容

| #   | 配置内容       | 说明                                                                                                      |
| --- | ---------- | ------------------------------------------------------------------------------------------------------- |
| 1️⃣ | **渠道费用**   | 游戏发布到指定渠道时，渠道方收取的费用，一般是按照流水的比例收取                                                                        |
| 2️⃣ | **支付通道费用** | 用户在游戏充值时使用的付费通道，通道方收取的费用，一般是按照流水的比例收取                                                                   |
| 3️⃣ | **CP 分成**  | 发行与 CP 对流水收入的分成管理，一般有比例 / 阶梯比例等综合管理方式；且需要考虑分成时用的是什么**节点**（支付渠道 / 通道费用**前或后**等）与什么**口径**（IAA 与 IAP 等）的流水 |

### 2.2 场景闭环

能支持财务人员**新增 / 编辑配置 → 计算结果回 BI 看板**这个过程闭环；并兼容考虑以下边界场景：

- 财务人员**忘记配置**
- 财务人员**配置错误后修改**
- **CP 合同变更**
